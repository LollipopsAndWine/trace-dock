# RFC 1：收集已有的 Codex / Claude workspace 和轨迹

2026-11-09

## 目的

把大家机器上已经跑过的 Codex 和 Claude Code 会话收集起来，每条包含两份东西：

- **最终 workspace**：会话所在的工作目录，跑完之后的样子。
- **轨迹**：工具自己记的会话日志，每一步模型说了什么、调了什么工具、改了哪个文件。

收来做什么：构造评测题。一道题需要一对数据——某个时刻的目录当输入，下一个时刻的目录当参考答案。轨迹提供过程，workspace 提供现场，缺一个都做不成题。

### 一条实测结论：这件事已经在丢数据

在一台本地机器上实测（2026-11-09）：

- Claude 的 `~/.claude/projects` 里最老的记录是 **10-09**，`.last-cleanup` 显示当天上午 09:49 刚清理过一次。**保留期大约 30 天，过期自动删。**
- 共享开发机上扫了 123 个用户，只有 2 个人的 Codex 会话还在（47 条），其中 **28 条（60%）的工作目录已经不存在了**。

所以采集要排在文档定稿之前。不是数据会变旧，是数据正在被删。

### 另一条实测结论：倒推这条路不通

存量数据只有「结果」，没有「起点」。收上来的目录是跑完之后的样子，会话开始时的状态已经被覆盖了。理论上可以拿轨迹倒推——轨迹里记了每次文件改动，一步步撤销就能回到之前的状态。

但实测的工具调用比例是：

| | shell 调用 | 文件编辑调用 | 比例 |
| --- | --- | --- | --- |
| Claude（340 个会话） | 12745 | 2583 | 4.9 : 1 |
| Codex（本地 11 个会话） | 141 | 4 | 35 : 1 |

**288 / 340 个 Claude 会话里，shell 调用多于文件编辑。** 真实工作方式是在 shell 里 `sed -i`、重定向、`cp`、`git checkout`，这些改动两个工具都不记。倒推在这里必然断，而且断了之后推出来的目录看着是完整的，只是内容错了。

结论：**倒推不回去的会话不做成题，只归档。** 本 RFC 只承诺两件事——摸清家底、抢救性归档。能出多少题，等数字出来再定。

## 实现

### 1. 两个工具分开处理，规则不共用

实测下来两边几乎没有共同点，不要试图写一套通用解析器。

| | Codex | Claude |
| --- | --- | --- |
| 轨迹位置 | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` | `~/.claude/projects/<编码目录>/*.jsonl` |
| 改动记录形式 | 只有 `unified_diff` | `Edit` 带 `old_string` + `new_string`，`Write` 带完整 `content` |
| 能不能倒推 | 不能（必须有基线反向打 patch） | 原则上能（有原文有新文） |
| schema | **有两套互不兼容的版本**，见 3 | 目前一套 |

### 2. Claude：必须递归扫，还要带上子 agent

只扫 `projects/*/*.jsonl` 会漏掉一半——实测一层是 340 个文件，更深层还有 **328 个**，路径形如 `<session-id>/subagents/agent-*.jsonl`。

这不只是漏文件：`Agent` 工具被调用了 317 次，**子 agent 做的文件改动不在主轨迹里**。只看主轨迹做可逆性判定，结论是错的。

采集范围写成 `projects/**/*.jsonl` 递归，同时记下每个文件属于哪个主会话。

### 3. Codex：按 schema 版本分支

实测两套格式字段名几乎没有交集：

- **旧版**（共享存储上 2026-05～10 的数据）：`type` = `response_item`，工具名 `apply_patch` / `exec_command`。
- **新版**（本地 2026-08～11 的数据）：`payload.type` = `item_completed` / `custom_tool_call`，工具名 `exec`，顶层多了 `ordinal` / `thread_name`。

版本号没有显式写在文件里，只能靠字段形状识别。解析器按形状分支，认不出的版本直接跳过并记录，不要猜着解析。

### 4. 先登记，再采集

每条记：人、机器、工具（codex / claude）、workspace 路径、轨迹文件路径、会话结束时间、采集时间。

后两个时间的差要单独记——人跑完之后又改了什么我们看不到，这个差越大越不可信。注意顶层目录的 mtime 不反映子目录改动，这个指标能发现问题，不能证明没问题。

### 5. 只取轨迹，不要整体打包

实测 `~/.claude` 整体 1530 MB，而轨迹只占 944 MB，其余是缓存、插件、备份。`~/.codex` 更极端：总共 1.2 GB，轨迹只有 20 MB。

精确只取轨迹文件，有两个好处：搬运量小，而且能绕开 `~/.claude/.credentials.json`、`shell-snapshots/`、`memories/` 这些不该出本机的东西。

另外 `~/.codex` 下有 `logs_2.sqlite` 带着 `-wal` / `-shm`，说明数据库正在被写——热拷贝会拿到不一致的数据，别碰。

### 6. workspace 按 cwd 性质分级采集

实测 cwd 经常不是一个项目仓：

| cwd 类型 | 实测例子 | 怎么处理 |
| --- | --- | --- |
| 正常项目目录 | 19209 文件 / 360 MB，扫一遍 2.1 秒 | 直接存 |
| 上层目录 | 81048 文件 / 3.4 GB，套着 30 个 `.git` | 只记路径，不存内容 |
| 家目录 | 11 个会话的 cwd 就是家目录 | 只记路径，不存内容 |
| 产物目录 | 训练日志目录、checkpoint 目录 | 只记路径，标注「非代码会话」 |

不分级就会出现为了一个看日志的会话去打包 3.4 GB 的情况。

### 7. 路径还原：只认 cwd 字段

Claude 的 `projects/` 目录名是对路径的有损编码，非 ASCII 全被替换成 `-`：`浦江` 变成 `---`，`硕士毕业` 变成 `-----`，不同路径只差连字符个数。**不能从目录名还原路径**，必须读 jsonl 里的 `cwd` 字段。

另外同一个目录可能被记成 `c:\Users\...` 和 `C:\Users\...` 两个 cwd。Windows 路径大小写不敏感但字符串比较敏感，去重前要先规范化。

### 8. 密钥清理在原机器上做

workspace 和轨迹都要扫 token、密码、私钥。轨迹更危险，命令输出会被原样记下来（实测有 583 条输出字段超过 500 字符）。

命中的文件整个排除，并在清单里记一条"因密钥排除"。不要原地替换内容——替换过的目录既跑不起来也没法核对。

搬完再集中扫不行，那时密钥已经出了原机器。

### 9. 大文件单独记一份清单

每条只记两个字段：

- **相对路径**：它原本在 workspace 里的位置。
- **远端路径**：它实际存在哪儿。要写成带机器名的完整形式，否则换台机器就找不到了。

远端路径优先从轨迹里找 `wget`、`curl`、`aws s3 cp`、`scp` 这类命令反查；查不到就填它此刻所在机器上的绝对路径。

**判定规则不能只看体积。** 实测纯阈值一条都没判对：一个 162 MB 的文件是分析结果（该进快照），而体积最大的几个文件全是 `.git/objects/pack/*.pack`（129 MB、94 MB、81 MB，出列了快照就残了）。规则写成三层：

1. 白名单优先——`.git/` 内部一律不出列；
2. 黑名单——按目录和后缀识别模型、权重、数据集、压缩包；
3. 体积阈值只做兜底。

规则写成独立配置文件，RFC 2 用同一份。

### 10. 其他要处理的情况

- **会话被压缩过**：Codex 的 `compacted` 事件（实测 47 条里有 5 条），中间内容被摘要替换，那一段的动作流重建不出来，直接标为不可倒推。
- **跨人目录**：实测有人的会话 cwd 指向别人的目录。找一个人要数据，实际会拿到好几个人的代码、路径和日志。授权范围要提前说清。
- **去重**：resume / fork 出来的多份按根会话归并，留最长那条。
- **有效性**：中断、超时、报错的会话归档但标为无效，不进题库。

### 11. 验收

出一张统计：按人、按工具的会话数 / workspace 还在的 / 能倒推的 / 只能归档的，以及大文件清单里远端路径填不出来的占比。

然后抽几条判为"能倒推"的，真的在另一台机器上倒推一次，比对文件树。对不上就先修判定规则，别带着错规则跑全量。

### 12. 和 RFC 2 对齐

共用一套 ID，共用同一份大文件判定规则。

ID 有现成锚点，不用自己编：Codex 的文件名自带 uuid（`rollout-<时间>-<uuid>.jsonl`），Claude 的文件名就是 session id。
